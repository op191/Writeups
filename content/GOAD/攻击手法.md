### 🎯 攻击手法全景概览

GOAD 的攻击链设计遵循典型的内网渗透生命周期：**侦察枚举 → 初始立足 → 本地提权 → 横向移动 → 跨域/跨森林提权 → 持久化**。

* **侦察与初始立足**：环境开放了匿名 RPC 枚举，可利用 `netexec` 或 `enum4linux` 直接获取用户列表，并在 `samwell.tarly` 的描述字段中找到明文密码 `Heartsbane`。`brandon.stark` 和 `missandei` 开启了“不需要预认证”，可直接进行 AS-REP Roasting。
* **权限提升与横向移动**：获取初始凭证后，通过 Kerberoasting 攻击 `jon.snow`、`sql_svc` 等服务账户。同时，利用 BloodHound 分析 ACL 滥用路径（如 `lord.varys` 对 `Domain Admins` 的 `GenericAll`）进行横向提权。
* **跨森林攻击（针对 essos）**：由于 SID 过滤的存在，无法直接伪造高权限票据。需要利用 `sevenkingdoms.local` 中 `Small Council` 组与 `essos.local` 中 `Spys` 组的跨森林嵌套关系，以 `tyron.lannister` 为跳板，重置 `jorah.mormont` 的密码来获取 `essos` 的立足点。
* **ADCS 证书攻击**：如果 ACL 路径受阻，`essos.local` 还部署了存在漏洞的 ADCS 服务（如 ESC13），一旦获得该域内任意普通用户权限，即可通过申请证书直接提权为域管。

### 🛠️ 关键攻击技术详解

#### 1. 初始凭证获取（无需密码）

GOAD 特意配置了几个“脆弱点”来让你获得第一个立足点：

* **描述字段泄露**：用户 `samwell.tarly` 的 LDAP 描述字段直接写着密码 `Heartsbane`。利用 `nxc ldap` 配合 `--query` 可直接读取。
* **AS-REP Roasting**：`north` 域的 `brandon.stark` 和 `essos` 域的 `missandei` 均开启了“不需要 Kerberos 预认证”。利用 `GetNPUsers.py` 可以直接请求到加密的 AS-REP 哈希，离线破解后即可获得明文密码。

#### 2. Kerberoasting 与 ACL 滥用

获得域用户权限后，下一步是寻找高价值目标：

* **Kerberoasting**：`jon.snow`（SPN: CIFS/thewall）、`sql_svc`（SPN: MSSQLSvc/castelblack）等账户的密码哈希可以离线破解。特别注意 `jon.snow` 还存在“约束委派”到 `winterfell` 的配置，拿到他的密码后可以利用委派权限冒充管理员访问域控。
* **BloodHound ACL 分析**：导入 BloodHound 后，重点查询 `Shortest Paths to Domain Admins`。例如在 `sevenkingdoms.local` 中，`lord.varys` 对 `Domain Admins` 组拥有 `GenericAll` 权限，可以直接把自己加入域管组。

#### 3. 跨森林攻击 essos 的路径

你目前的困境核心在于 SID 过滤。绕过它的方法不是伪造信任票据，而是利用**合法的跨森林组嵌套**：

* **`Small Council` → `Spys`**：`sevenkingdoms.local` 的 `Small Council` 组被 `essos.local` 的 `Spys` 组接纳为成员。这意味着 `Small Council` 里的用户（如 `tyron.lannister`）在 `essos` 里自动拥有 `Spys` 的权限。
* **重置 `jorah.mormont`**：`Spys` 组对 `essos.local` 的用户 `jorah.mormont` 拥有 `GenericAll`。利用 `tyron.lannister` 的凭证，可以直接重置 `jorah.mormont` 的密码，从而获得 `essos` 域内的第一个有效立足点。

#### 4. 针对 essos 的 ADCS 捷径

如果你在 `essos` 内部获得了任意普通用户凭证，可以尝试更直接的 ADCS 攻击：

* **ESC13 模板**：`essos.local` 的 ADCS 上存在一个与特权组 `greatmaster` 关联的模板。任何能注册该模板的用户，KDC 都会在签发的 PAC 中注入 `greatmaster` 组的 SID，直接获得域管权限。
* **ESC15 模板**：`WebServer` 模板是 schema version 1，允许 `EnrolleeSuppliesSubject`。可以利用它注入任意应用策略，冒充高权限用户进行客户端认证。
