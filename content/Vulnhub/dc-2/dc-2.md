
1.先 nmap -sn ip 扫描出目标；然后用nmap -sV -p- ip 扫描全端口，这里一定要扫全端口，如果只用-sV 只能扫出80端口，还有一个7744的ssh端口扫不出来， 

2.访问网站发现输入ip后，返回的却是域名还有连接不上网站，说明服务器对该网站使用了重定向，返回个域名给浏览器，但是浏览器无法去公网的域名解析服务器解析这个ip,因为这是本地的ip域名转换，因此要在操作系统修改本地的域名解析，让浏览器去本地找域名解析；还有就是服务器的应用层会校验http请求包的host字段，(该字段说明要访问的服务器，可以是域名，也可以是ip,)该靶机会校验host是不是dc-2，这个域名，如果不是就给你返回重定向，如果是就让你进入网站，因此不改本地域名解析也可以bp抓包改host的内容为域名，也能绕过（注意，这是应用层，不会说把host ：192.168.18.136改为host :  dc-2 ,数据包就找不到服务器了，找服务器的事是在网络层的ip协议）

3.进入网站后发现无法上传webshell,或者是修改模块添加恶意代码来获取服务器的shell。

发现是个WordPress 的cms,可以利用该cms的接口wp/-jsonn/wp/v2/手动获取用户名，有3个用户名，访问该网址只能有2个用户名出来，一个是待会用密码爆破不出的，另一个是普通权限的用户，手工不出的那个是待会通过ssh登陆用的，所以只能用工具wpscan去枚举用户名，将3个用户全部枚举出来。刚才说了，网站没入口，所以想到另一个7744端口，因为我们已经爆破出网站后台的2个用户和密码，考虑去撞库，用网站的用户密码去登陆ssh,有一个是登陆ssh显示权限不够，还有一个是可以ssh登陆的，但是开启的shell是rbash,(受限制的shell,权限超低，)，所以需要进行rbash逃逸，进入另一个终端shell，进入目录发现有vi可用，打开vi,输入！/bin/bash,强制打开一个新bash,但是打开后的bash会继承原来系统的环境变量，rbash的shell也是系统的环境变量，更可怕是还设置了readonly variable ;

打开新bash第一件事就是export PATH=$PATH:/bin/:/bin/usr:/usr/bin  改环境变量，改了后发现很多命令还是用不了，输入export，发现shell字段依旧是/bin/rbash 说明还没逃逸成功，没逃逸出rbash范围，但是我们可以修改环境变量了，能用之前一些不能用的命令了，说明距离它的范围边界越来越近了，然后发现  su  命令可以用，就是切换用户，因为我们刚才已经爆破出两个用户和密码，那个直接用密码登陆显示权限不足的，我们现在用su - 用户名  来切换该用户，这是因为 系统配置 禁止该用户直接ssh登陆，但是没有禁止su切换该用户

切换用户后，再输入export,  发现shell字段变为：/bin/bash， 说明我们已经从rbash逃逸出来啦，

sudo -l 显示可以提权用的命令，发现有一个，还不需要密码 git命令；用sudo git help config打开分页器，就是一个文本编辑器，Linux的文本编译器一般都有一个shell用来配置文件的，还有保存退出什么的，我们利用这个shell打开/bin/bash，bash由分页器程序加载，分页器程序由git 加载，sudo 的git 具有root权限，所以新开的bash具有root权限；
